## 1. What the data is

All data is **synthetic and generated on demand** by a seeded simulator. There is no real warehouse,
customer, worker or sensor data, and no personal data of any kind. A "dataset" here is a set of
*scenarios*: a seed fully determines the map, the robots' initial batteries, the order stream and
the sensor noise, so any episode can be regenerated byte-for-byte.

| Item | Value |
|---|---|
| Environment contract | `warehouse_v6_research` ([src/environment/spec.py](../src/environment/spec.py)) |
| Observation contract | `egocentric_range_v3_pose_feedback`, 348 features per robot |
| Workload | `mixed_stock_v1` ([src/environment/mixed_logistics.py](../src/environment/mixed_logistics.py)) |
| Actions | 7: FORWARD, BACKWARD, LEFT, RIGHT, WAIT, SERVICE, REQUEST_CHARGE |
| Episode length | 600 ticks |

## 2. Warehouse geometry (identical for N = 5, 10, 20)

A fixed 20 × 20 grid (`fixed_map` scaling). Demand does **not** grow with fleet size, so larger
fleets face more congestion for the same work.

| Cell code | Meaning | Count |
|---|---|---|
| 0 | Free aisle | 243 |
| 1 | Shelf / rack (impassable) | 60 |
| 2 | Human-worker safety corridor (never enterable) | 76 |
| 3 | Pickup / storage bays (12) + receiving docks (2) | 14 |
| 4 | Shipping (drop) bays | 4 |
| 5 | Chargers | 2 |
| 6 | Transfer bay | 1 |

The centralised critic's global state grows with the fleet: 2226 (N=5), 2331 (N=10), 2541 (N=20).

## 3. Scenario generation (`make_mixed_scenario`)

- **Order stream.** One external package arrives every `interval` ticks (default 20) during the
  first two-thirds of the shift (ticks 0–399). Each arrival creates an *inbound* put-away job
  (receiving dock → storage bay) and an *outbound* shipping job 40 ticks later (storage bay →
  shipping bay). At the default interval that is 20 packages = 40 orders per episode. Bays and
  docks are drawn uniformly at random from the seed's RNG. Deadline 240 ticks, priority 1.
- **Robots.** Battery capacity × U(0.7, 1.1), starting state of charge U(0.35, 1.0), energy
  consumption factor U(0.8, 1.2), per robot.
- **Sensing noise.** 5% cell dropout, 1-tick latency, 5 × 5 egocentric window (12 channels).

## 4. Partitions (disjoint seed ranges)

| Partition | Seeds | Used for |
|---|---|---|
| Train (RL episodes) | 100000–189999 | Online RL rollouts |
| Expert demonstrations | 120000 + 100·seed + i | Behaviour cloning from the planner |
| DAgger corrections | 130000 + 100·seed + … | On-policy expert relabelling |
| **Sealed test** | **200000–200019** | Final benchmark only — never used for training or selection |
| Development | 300000–300004 | Checkpoint selection during training |
| Arrival-rate stress | 410000+ | Held-out demand-rate sweep |
| Drift monitor | 520000+ (reference), 530000+ (current) | Task-queue drift checks |

`demonstration_case` rejects any seed outside 100000–199999, so expert data cannot leak from the
sealed or development ranges.

## 5. Integrity

- Every scenario manifest carries a SHA-256 `scenario_hash` over its full contents (layout,
  events, initial robots, config).
- The scalability benchmark ([scripts/evaluate_scalability.py](../scripts/evaluate_scalability.py))
  asserts that every policy at a given N saw exactly the same scenario hashes before any paired
  comparison is computed.
- Trained checkpoints record the scenario hashes they trained on, plus a source-code hash and git
  revision, in their metadata.

## 6. Drift monitoring

[scripts/monitor_drift.py](../scripts/monitor_drift.py) compares the live task queue against the
normal-demand reference with Evidently's Population Stability Index on four features: order
inter-arrival gap, pickup-to-delivery route length, inbound/outbound share and live queue length.
PSI > 0.25 on any feature triggers retraining. Results: `outputs/monitoring/drift_report.json`.

## 7. Known limitations

- One fixed map. There is no out-of-distribution layout benchmark yet.
- Uniform bay selection; no seasonality, SKU popularity skew or correlated demand.
- The battery and motion models are synthetic and not calibrated to any real robot.
- Worker corridors are static; real workers move.
