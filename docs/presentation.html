01. Project Introduction & Background

Domain Architecture: Classical Centralised vs MARL CTDE

Classical Centralised (CBS / A*) Exponential Bottleneck O(b^N)
  • Runtime Explosion: Central computation locks up as fleet size exceeds 10 robots.
  • Single Point Failure: Communication latency halts the entire fulfillment line.
Our Solution: CTDE (QMIX) Fast Local Inference < 20ms
  • Decentralised Execution: Onboard policy acts directly on local 7x7 FOV without communication.
  • Zero Bottleneck: Scales seamlessly up to N=20 robots with constant latency.
1. Collision Hazards 0% Target

Physical AMR crashes damage inventory and cause floor downtime.

2. Aisle Deadlocks < 1% Rate

Head-on stalls in narrow corridors paralyze fleet traffic.

3. Suboptimal Orders ≥ 120 / hr

Static dispatching fails to balance picking station queues.

03. AI/ML Solution Architecture

QMIX Architecture, Hard Action Masking & MLOps Pipeline

1. Non-Stationarity

Central mixing network conditions on true global state during offline training to stabilize value convergence.

2. Evaluation Gate

100 held-out seeds tested with Welch t-test & Wilcoxon signed-rank tests (p < 0.05) against IQL and Rule baselines.

3. Live Telemetry

Continuous structured logs monitoring inference latency (<20ms), safety mask overrides, and deadlock watchdogs.

4. Retraining Loop

Automated shadow training triggered upon layout drift detection or fleet scaling expansions beyond N=20.

  • Risk: Scalability drop and credit assignment non-stationarity at N=20.

07. System Requirements

Requirements Engineering: Functional, Non-Functional, Data & Ethics

Functional (FR) System Behaviors
  • FR-1 (Decentralised Inference): Individual robots decide moves in < 50ms using 7x7 FOV.
  • FR-2 (Deadlock-Free Pathfinding): Multi-robot fleet navigates narrow corridors without mutual stalls.
  • FR-3 (Dynamic Task Dispatch): Automated order reassignment upon successful package delivery.
Non-Functional (NFR) Performance SLAs
  • NFR-1 (Zero Collisions): 0 physical collisions across all 100 evaluation seeds.
  • NFR-2 (Scalability): Maintain > 80% throughput efficiency scaling from N=5 to N=20.
  • NFR-3 (Latency Budget): Decision latency ≤ 20ms per agent on single CPU core.
Data Requirements (DR) Tensors & Replay
  • DR-1 (State Encoding): 7x7x3 normalized tensor for obstacles, teammates, and target vectors.
  • DR-2 (Replay Buffer): 5,000 multi-agent episode buffer storing state-action-reward tuples.
  • DR-3 (Evaluation Split): 100 fixed seed manifests locked via SHA-256 cryptographic hashes.
Ethics & Governance (ETH) Safety & Trust
  • ETH-1 (Safety Layer Inviolability): Learned policies can never bypass the safety mask.
  • ETH-2 (Audit Log Transparency): Structured telemetry for all safety overrides and deadlock events.
  • ETH-3 (Reproducibility Seal): Replicable benchmarks runnable from public GitHub repository.
